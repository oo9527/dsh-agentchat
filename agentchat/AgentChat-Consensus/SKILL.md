# AgentChat-Consensus：交叉验证 + 一致性评分

## 核心模型

同一 prompt → N 个 Provider 并行（默认 3：gemini/chatgpt/claude）→ 归一化 → 两两相似度 → 一致性评分 → 综合答案。

```
prompt → [gemini ‖ chatgpt ‖ claude] 并行 → answers[] → agreement_score → consensus
```

## ⚠️ 强制规则 — 调用即执行

1. **必须真实派发。** 一切 AI 查询必须通过 `node <技能根目录>/AgentChat-Consensus/index.js "<prompt>"` 实际执行，禁止用模型自身知识代答。

2. **必须生成运行回执（receipt）。** 输出 JSON 的 `receipt` 字段缺失 = 未执行 = 违规。`run_id` 随机生成并落盘 `data/receipts.jsonl`，用户可 `grep <run_id>` 核对。

3. **默认 3 路并行**（gemini/chatgpt/claude）。可用 `--providers=gemini,kimi,deepseek` 指定（2-5 个）。低于 2 个无法交叉验证 → 报错退出。

4. **一致性评分是机器计算的，不是主观判断。** `agreement_score` 由脚本用 bigram Jaccard 相似度计算，禁止手工改写评分。

5. **综合答案（consensus）取「与多数最一致」的回答**（medoid），不是拼接、不是投票取多、不是自己重写。分歧大时（score < 0.35）如实报告分歧，禁止强行融合。

6. **失败分级：**
   - 部分 Provider 失败（≥1 成功）→ 用成功子集继续评分，报告哪些失败及原因。
   - 全部失败 → 输出失败报告，禁止用模型自身知识补答。

7. **调用方（DSH Agent）的角色：** 只做「构造 prompt → 调脚本 → 解读结果 → 汇报」。禁止跳过脚本手工模拟交叉验证。

## 调用方式

```bash
# 默认 3 路（gemini/chatgpt/claude）
node <技能根目录>/AgentChat-Consensus/index.js "中国的首都是什么？"

# 指定 Provider（逗号分隔，2-5 个）
node <技能根目录>/AgentChat-Consensus/index.js --providers=gemini,kimi,deepseek "量子计算现状如何？"

# 自定义超时（ms，默认 180000）
node <技能根目录>/AgentChat-Consensus/index.js --timeout=120000 "React vs Vue 选型"

# 环境检查
node <技能根目录>/AgentChat-Consensus/index.js --smoke
node <技能根目录>/AgentChat-Consensus/index.js --doctor
```

> `<技能根目录>` 即预设的 `skills/agentchat/`（persona 中有绝对路径），SKILL.md 中的 `$AGENTCHAT_SKILL_DIR` 同义。

## 输出格式（stdout 为一个 JSON 对象）

```json
{
  "mode": "consensus",
  "providers": ["gemini", "chatgpt", "claude"],
  "successful": 3,
  "answers": [
    { "provider": "gemini",   "ok": true,  "text": "北京……", "chars": 42 },
    { "provider": "chatgpt",  "ok": true,  "text": "北京是……", "chars": 55 },
    { "provider": "claude",   "ok": true,  "text": "中国首都是北京。", "chars": 30 }
  ],
  "agreement_score": 0.91,
  "verdict": "high",
  "consensus": "北京……",
  "pairwise": { "gemini↔chatgpt": 0.9, "gemini↔claude": 0.88, "chatgpt↔claude": 0.95 },
  "elapsed_ms": 45210,
  "receipt": { "run_id": "ac-xxxxxxxx", "skill": "AgentChat-Consensus", "exit": 0 }
}
```

### verdict 阈值

| score | verdict | 含义 |
|-------|---------|------|
| ≥ 0.60 | `high` | 高度一致，consensus 可信，直接采纳 |
| 0.35–0.60 | `partial` | 部分一致，consensus 供参考，需说明分歧点 |
| < 0.35 | `low` | 分歧大，列出各答案，明确告知「无一致结论」 |

## 输出排版规范

调用方（DSH Agent）最终回答遵守：
1. **结论先行**：开头给出 verdict + agreement_score（如「3 个 AI 高度一致（0.91）」）。
2. **综合答案优先**：先给 consensus，再给各 Provider 差异（如必要）。
3. **分歧如实报告**：`low`/`partial` 时列出分歧点，不掩盖。
4. **receipt 保留**：末尾引用 `receipt.run_id`。
5. 禁止出现 Provider 徽章、覆盖矩阵、"Generated by…"。

## 技术说明

- 相似度算法：文本归一化（小写、去空白标点）→ 字符 bigram 集合 → Jaccard 系数。
- 并行度受浏览器准入槽（`AGENTCHAT_MAX_CONCURRENT_PAGES`，默认 3）约束；超过时排队。
- 复用共享 worker 池（v27），Provider 调用走 `--only`/`--single` 语义，无内部级联。
- 每个 Provider 独立会话，无跨 Provider 上下文传递。
